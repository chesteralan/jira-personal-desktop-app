# Jira Provider Contract

`JiraProvider` is an internal Rust port implemented first by `JiraCloudProvider`.

## Capabilities

- Verify credentials and retrieve current identity/site metadata.
- Discover projects and boards with pagination.
- Search issues using bounded JQL and field selection.
- Retrieve an issue, transitions, priorities, sprint/board metadata, and comments as permitted.
- Execute a transition, change priority, and add a comment.
- Classify authorization, permission, validation, rate-limit, transient, and permanent failures.

## Invariants

- Every list operation exposes pagination/cursor state and cancellation.
- Requests use explicit timeouts and bounded retry; non-idempotent writes are not blindly retried.
- Authorization and user-generated payloads are redacted before diagnostics.
- Provider DTOs are mapped to domain entities before persistence.
- Missing fields and permission restrictions are represented explicitly, not treated as empty success.
- JQL fragments generated by the app are parameterized/escaped by a dedicated builder; custom JQL is validated and never concatenated with hidden clauses without visible disclosure.

## Contract verification

Fixture tests cover representative Cloud responses, malformed/partial data, pagination, 401/403/404/429/5xx, invalid JQL, transition races, and ADF content. Sandbox tests run separately because they require credentials and perform real mutations.
